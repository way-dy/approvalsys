# 구조 — 단일 파일·Firestore 데이터 모델·Firebase 설정

> 정본. 루트 `CLAUDE.md` 가 @import 한다.

### Single-file structure

`public/index.html` contains everything: an inline `<style>` block, an inline `<script type="module">` containing all JS (Firebase init, state, data access, rendering, event handlers), and the full DOM for every "view" (login, app shell, sidebar, modals). Views are toggled by adding/removing `.hidden` on top-level containers (`#login-view`, `#app-view`, `#modal-draft`, `#modal-detail`, etc.). There is no router and no framework — DOM is updated by direct `innerHTML` assignment and `document.getElementById` lookups.

When editing, use the `// =====` comment banners as section markers; the file is logically organized as: Firebase init → cache helpers → init/auth flow → meta loading → drafts loading → search → render/pagination → save/approve actions → admin actions → DOM/HTML.

### Firestore data model

Collections used (all referenced as string literals — grep `collection(db,` to find every read/write site):

- **`drafts/{docId}`** — full draft documents. `docId` format is `YYYY-NNNN` generated by an atomic `runTransaction` against `meta/counters`. Fields include `title`, `content` (HTML), `category`, `corporation`, `drafter*`, `approver1*`/`approver2*`, `approval1Status`/`approval2Status` (`'결재'` | `'반려'` | `null`), `approval1Comment`, `paymentDate`, `finalApprovalDate`, `rejectionAckedBy[]` (이메일 배열 — 반려 문서를 본인이 열람해 NEW 표시를 해제한 사용자 추적; 본체는 `arrayUnion`으로 갱신), `attachments[]`, `refLinks[]`, `createdAt` (serverTimestamp).
- **`drafts_index/{docId}`** — lightweight mirror of `drafts` **without** `content`/`attachments`/`refLinks`, plus a `searchTokens` array (1–4-gram of `title + drafter + category + corporation`, capped at 500). Primary list-view source. `buildIndexDoc` writes: `docId`, `title`, `category`, `corporation`, `drafter*`, `date`, `createdAt`, `approver1/2*`, `approval1/2Status`, `approval1/2Comment`, `finalApprovalDate`, `paymentDate`, `rejectionAckedBy`, `searchTokens`. Every write to `drafts` must be mirrored via `saveIndexDoc` (full setDoc) or `updateIndexDoc` (partial). `updateIndexDoc` whitelists 7 fields — `approval1/2Status`, `approval1/2Comment`, `finalApprovalDate`, `paymentDate`, `rejectionAckedBy` (배열은 항상 평문으로 미러 — `arrayUnion` 센티넬을 넘기면 폴백의 `buildIndexDoc`가 `[]`로 깨뜨림) — **결재자 변경처럼 화이트리스트 밖 필드를 같이 바꾸는 흐름(`adminSaveApprovalStatus`)은 반드시 `saveIndexDoc(fullSyncedData)`를 써서 인덱스 전체 재작성**. Composite index: `drafterEmail ASC + createdAt DESC` (myDrafts 쿼리), `searchTokens array-contains + createdAt DESC` (전체 검색). 둘 다 `firestore.indexes.json`에 정의 — `firebase deploy --only firestore:indexes`.
- **`meta/users`** — `{ list: [{ email, name, team, role, isAdmin, approvalOnly, confidentialAccess, ... }] }`. The Firebase Auth user is matched against this list by email to populate `currentUser`. Users not in the list get `role: '미등록'`.
- **`meta/repairMap`** — lookup map for the 수리비 (repair fee) workflow.
- **`meta/counters`** — `{ year, count }` for atomic doc-ID generation.
- **`accessLogs/{auto}`** — append-only audit trail for confidential (`대외비`) document views and file opens.

Firebase Storage holds attachments under `attachments/{timestamp}_{filename}`. Files are opened by fetching the URL and creating a Blob URL (workaround for Chrome PDF CORS issues); confidential file opens always log to `accessLogs` first.

### Firebase config

`firebase.json` only configures hosting (`public: "public"`). `.firebaserc` pins project `approval-8ef73`. The Firebase Web API config is hardcoded inline in `index.html` (`firebaseConfig` object near line 88) — this is a public client config and is intentionally committed. 최초 로그인은 `signInWithPopup(GoogleAuthProvider)`이고, 대외비 재인증은 **`reauthenticateWithPopup(auth.currentUser, provider)`** 사용(아래 "중요 이슈 기록" 참조). `@dongyeongtour.co.kr` 도메인 외 계정은 `onAuthStateChanged`에서 즉시 차단/로그아웃.
